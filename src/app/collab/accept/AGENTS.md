# Accept constraints

- Acceptance is an online authority decision over the exact reviewed main/head, request revision, and resolving-Ticket revisions, even when Manager and Host differ.
- Validate the full candidate tree and relation capacity before Git mutation and again during recovery/finalization. Never check out or rewrite a Member branch.
- An incomplete Accept locks both its request and resolving Tickets. Cross-store recovery must distinguish a prepared result from an already-applied main ref; unexpected main movement disables Accept rather than guessing.
- Final request/Ticket/event/idempotency state commits together. Changes to those locks/finalization must also follow `../authority/AGENTS.md`.
