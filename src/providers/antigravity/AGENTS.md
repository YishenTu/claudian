# Antigravity constraints

## Session creation and recovery

- Authentication is native: never call ACP `authenticate` or store Google credentials. Auth failures point to `agy acp --login`.
- Never fall back from `session/resume` to `session/load`: agy answers load for any id, then fails the next prompt (`trajectory not found`). A missing-session error keeps the binding; `historySessionId` locators written by earlier versions stay readable because transcripts outlive the session database. A failed immediate resume after creation keeps the new native id for retry.
- The native store follows HOME (USERPROFILE on Windows); launch changes, including a moved store, keep bindings and reload them.
- Main chat runs on agy's default agent, so its persona, guidelines, vault rule files and tool set (including subagents) stay. Claudian's prompt goes only in `session/resume` `_meta.antigravity.systemPrompt.append`: agy stores a `session/new` append permanently and stacks later appends on it, while a resume append is not stored and each one replaces the last. Every resume therefore sends the current prompt, and a changed prompt re-resumes the open session before the next turn.
- Auxiliary sessions (title, Inline Edit) need tool restriction, which only custom agents provide (agy ignores `disableBuiltInTools` on its default agent). Their agent body and tools are frozen at native session creation; select and prepare agent files only for `session/new`, never send them an append, and resume existing ids without file checks or agent selection.
- Every new session is resumed in the same process before its first prompt: that resume delivers the main append and installs a custom agent's ACP MCP servers. Publish the created id before resume; mark it loaded only after resume succeeds so failures can retry the same id. Auxiliary sessions carry no MCP servers: an empty native tool list does not block MCP tools.
- Claudian owns only marked generated `agent.md` files, not their directories. Refuse foreign or malformed files; file failures must prevent native creation rather than silently use agy's default agent.
- Off because agy's ACP server lacks them: fork, rewind, ephemeral sessions, fast mode.

## Models and discovery

- Each session's config options are authoritative for the model catalog; ACP rejects models it did not advertise. Apply model, `thought_level` and mode with `session/set_config_option` only when they differ, and retire the process when cancellation interrupts that step so the cached values cannot go stale. `thought_level` is reported only for the current model and is absent for fixed-effort models; send none when the session offers none. Per-model levels come only from the legacy `models.availableModels` list in session/new and resume responses.
- Prefer live `available_commands_update` and config options; the prompt-less discovery probe is unlisted but leaves a native session directory.
- Unsupported built-in commands are hidden by name (`ANTIGRAVITY_HIDDEN_COMMANDS`) because agy marks no command as built-in.

## Permissions and tools

- agy never relays a subagent's approval request over ACP, so outside native Auto a subagent that needs approval stalls (accepted limitation for Ask and Accept edits). YOLO main chat therefore runs in a process launched with `--dangerously-skip-permissions`, which overrides every mode until restart: entering or leaving YOLO replaces the process. Auxiliary sessions never get the flag; their read-only and passive policies depend on Claudian denying requests. Never select native `plan`; Claudian has no plan mode.
- Auxiliary agent files exclude subagent tools (built-in subagents are unavailable under a custom agent, upstream #1225). Main chat cannot exclude them; their results arrive after `end_turn` and never stream.
- `ask_question` arrives as form `elicitation/create` only when the client advertises elicitation; answer with option `const` values (match them before labels) and free text in `<field>_other`. Its completed update omits the answers, so the question router supplies them to the tool result by tool call id.

## Streaming and history

- agy echoes a prompt that starts a turn and a steer when it injects it, stripping a leading slash-command name; `/compact` and images are not echoed. Steering is confirmed by that echo or by the turn completing.
- Work that finishes after `end_turn` (long background commands, slower subagents, schedules) never streams; it lands only in the transcript. agy answers a subagent's report on its own (a `SYSTEM_MESSAGE` whose sender is the subagent's `conversationId`, then a reply). While a main-chat subagent is outstanding between turns, `AntigravityAutomaticResponseFollower` watches the transcript and publishes each finished automatic reply as one background turn, built by the history parser. Only replies that start after their live turn's boundary are published: the last transcript step at the first transcript read that begins after the turn's prompt settled. agy records steps before streaming them, and its prompt can settle seconds after a report it already answered in-turn; a reply agy writes between the settle and that read (milliseconds, while its late writes lag seconds) is treated as streamed (accepted). Only prompted turns record a boundary, and the first one recorded for a request stands. Following blocks idle release and ends after 30 minutes without a transcript change; where the directory cannot be watched, a poll counts only a changed file revision. A subagent outstanding when agy's process ends did not run after resume (probe 19) and its transcript stays "created, never reported", so ending a process stops following and only subagents created from that process's first recorded request count as outstanding; that request is the turn's latest, so a steer after the first launch in a process ends following early and the reply shows on reload (accepted). agy streams what it did between turns (its own replies, a background command's completion) again at the start of the next prompt, before that prompt's echo; a run drops output until its echo, except for prompts agy does not echo (`/compact`, image-only), where the replay stays in the turn (accepted).
- A prompt response's usage sums every model call in the turn. The context meter uses the transcript's last `PLANNER_RESPONSE` (`input_tokens + cache_read_tokens`) and reports no context when that is unreadable; never fall back to the sum.
- agy reports compaction only as a transcript `CHECKPOINT`: live, a `/compact` prompt that completes (not a steer that took over) is the boundary. Transcript `SYSTEM_MESSAGE`s from a task sender are notifications; `sender=system` notices are only context.
- Transcripts have no cancellation or steer marker. On replay, trailing unfinished model/tool output carries `isInterrupt` and no completion timing; a final planner reply without tools, a completed checkpoint, or a terminal `permission check failed` result completes it (denial also completes live). `USER_INPUT` may be a steer and task reports may arrive mid-run, so neither boundary proves an interruption. Empty/system-only segments do not prove a stop; a trailing incomplete snapshot cannot distinguish cancellation from another client's running turn. Background launch `RUNNING` status is not a turn outcome.
