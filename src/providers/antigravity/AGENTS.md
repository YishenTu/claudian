# Antigravity constraints

## Session creation and recovery

- Authentication is native: never call ACP `authenticate` or store Google credentials. Auth failures point to `agy acp --login`.
- Never fall back from `session/resume` to `session/load`: agy answers load for any id, then fails the next prompt (`trajectory not found`). A missing-session error keeps the binding; `historySessionId` locators written by earlier versions stay readable because transcripts outlive the session database. A failed immediate resume after creation keeps the new native id for retry.
- The native store follows HOME (USERPROFILE on Windows; the distro's Linux HOME, read through the distro, for WSL installations); launch changes, including a moved store, keep bindings and reload them. Under WSL agy reports Linux paths: map only agy's top-level tool arguments (`Path`, `AbsolutePath`, `Cwd`), ACP locations and diff paths to host paths (nested MCP arguments stay literal), live and in history, and poll the subagent transcript instead of relying on change notifications over the distro share.
- Main chat runs on agy's default agent, so its persona, guidelines, vault rule files and tool set (including subagents) stay. Claudian's prompt goes only in `session/resume` `_meta.antigravity.systemPrompt.append`: agy stores a `session/new` append permanently and stacks later appends on it, while a resume append is not stored and each one replaces the last. Every resume therefore sends the current prompt, and a changed prompt re-resumes the open session before the next turn.
- Auxiliary sessions (title, Inline Edit) need tool restriction, which only custom agents provide (agy ignores `disableBuiltInTools` on its default agent). Their agent body and tools are frozen at native session creation; select and prepare agent files only for `session/new`, never send them an append, and resume existing ids without file checks or agent selection.
- A new main session needs an immediate resume for its prompt append. A fresh custom agent already has its body and native tools, but needs a resume if it receives ACP MCP servers. Publish the created id before a required resume so failures can retry it. Auxiliary sessions carry no MCP servers because an empty native tool list still permits MCP tools. WSL installations attach session tools as a stdio server through the Windows interop relay, since Linux cannot reach the host loopback under default NAT.
- Claudian owns only marked generated `agent.md` files, not their directories. Refuse foreign or malformed files; file failures must prevent native creation rather than silently use agy's default agent.
- Off because agy's ACP server lacks them: fork, rewind, ephemeral sessions, fast mode.

## Models and discovery

- Each session's config options are authoritative for the model catalog; ACP rejects models it did not advertise. Apply model, `thought_level` and mode with `session/set_config_option` only when they differ, and retire the process when cancellation interrupts that step so the cached values cannot go stale. `thought_level` is reported only for the current model and is absent for fixed-effort models; send none when the session offers none. The legacy `models.availableModels` list advertises exact model/effort IDs. When switching models, one such ID can apply an explicit effort with the model.
- Prefer live reports. Use `agy models` for standalone model discovery. Its variant list omits the current model, and a lone effort suffix can be part of a fixed model ID. Slash commands require ACP. Even creating an unlisted, prompt-less session can evict older native history.
- Unsupported built-in commands are hidden by name (`ANTIGRAVITY_HIDDEN_COMMANDS`) because agy marks no command as built-in.

## Permissions and tools

- agy never relays a subagent's approval request over ACP, so outside native Auto a subagent that needs approval stalls (accepted limitation for Ask and Accept edits). YOLO main chat therefore runs in a process launched with `--dangerously-skip-permissions`, which overrides every mode until restart: entering or leaving YOLO replaces the process. Auxiliary sessions never get the flag; their read-only and passive policies depend on Claudian denying requests. Never select native `plan`; Claudian has no plan mode.
- Auxiliary agent files exclude subagent tools (built-in subagents are unavailable under a custom agent, upstream #1225). Main chat cannot exclude them; they report after `end_turn`, and agy's reply to each report streams in a background turn.
- `ask_question` arrives as form `elicitation/create` only when the client advertises elicitation; answer with option `const` values (match them before labels) and free text in `<field>_other`. Its completed update omits the answers, so the question router supplies them to the tool result by tool call id.

## Streaming and history

- Claudian supports only current agy (the settings tell users to keep it updated). agy echoes no prompt or steer and replays nothing it did between turns, so Claudian emits every user boundary itself. A steer is confirmed when agy answers the prompt it takes over, or when the turn completes.
- agy streams what it does on its own after `end_turn` (its reply to a subagent's report or a finished background command, with tool calls and approval requests) live on the session, with no echo, start or end. Main chat shows it as one background turn, closed once nothing follows a `usage_update` for a second (agy ends every model call with one and streams that call's tools within milliseconds) or at the failure of a call Claudian did not approve; closing early only splits the reply. A run holds its prompt until that turn closes: agy finishes its own reply, including a pending approval, before answering, and a fast answer would otherwise join the reply. A reply that ends any other way without a `usage_update` holds the next prompt until Stop (accepted). Between runs, approvals, questions and session tools follow the latest run's policy and fail closed; auxiliary sessions get no background turn and keep denying. `session/cancel` also stops agy's background tasks and subagents, and after a Stop between runs agy reports the calls it ended as `tool_call_update`s, which must not open a turn. A prompt agy answers counts as received even when cancelled before any output. An update for a call the turn has not seen (a background command an earlier turn launched) is shown as that call.
- agy reports no subagent lifecycle over ACP. While a main-chat subagent is outstanding between turns, `AntigravitySubagentWatcher` reads the transcript (a report is a `SYSTEM_MESSAGE` whose sender is the subagent's `conversationId`) and holds idle release until every subagent has reported, or 30 minutes pass without a transcript change; where the directory cannot be watched, a poll counts only a changed file revision. A subagent outstanding when agy's process ends did not run after resume (probe 19), so ending a process stops watching and only subagents created from that process's first recorded request count; that request is read at the first successful transcript read after a turn's prompt settles. A steer after the first launch in a process can end watching early (accepted).
- A prompt response's usage sums every model call in the turn; never use it as context. The context meter shows the turn's latest `usage_update` (`used`/`size`) as reported, even though agy compacts Gemini at 256,000 tokens. A `/compact` turn's report still measures the old context, so that turn reports none; a turn without a report hides the meter.
- agy reports compaction only as a transcript `CHECKPOINT`: live, a `/compact` prompt that completes (not a steer that took over) is the boundary. Transcript `SYSTEM_MESSAGE`s from a task sender are notifications; `sender=system` notices are only context.
- Transcripts have no cancellation or steer marker. On replay, trailing unfinished model/tool output carries `isInterrupt` and no completion timing; a final planner reply without tools, a completed checkpoint, or a terminal `permission check failed` result completes it (denial also completes live). `USER_INPUT` may be a steer and task reports may arrive mid-run, so neither boundary proves an interruption. Empty/system-only segments do not prove a stop; a trailing incomplete snapshot cannot distinguish cancellation from another client's running turn. Background launch `RUNNING` status is not a turn outcome.
