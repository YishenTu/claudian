# DeepSeek Harness constraints

- Preserve the user's existing native Web profile, credentials, model defaults and MCP configuration. Presets are invocation overlays; do not provision a Claudian profile or reconstruct native configuration. The three bundled plugins stay narrow: compatibility (literal per-preset prompt files, live chat code-mode presentation and native auxiliary tool restrictions), lifecycle (exit when Claudian's end of stdin closes) and ephemeral (below). Harness owns tool execution, permissions and persistence.
- One workspace-owned `DeepSeekHost` runs a single native process for every DeepSeek session and history read. Only it starts, reconnects or stops the process; sessions attach through leases. `DeepSeekRoster` is the only subscriber to process-global streams and routes interactions to the nearest claimed subagent ancestor; forks name their source as native parent but are independent roots. A native session has at most one claimant per Host.
- Native exposes no close-session RPC: touched sessions keep their writers, and ephemeral sessions their memory, until the process stops. A second process claiming one gets `session/writer-held`; never remove native locks to make a read or resume succeed. Read cold history through projections and fixed-cut pages, and pre-session skill catalogs through `skills/list`; following a cold child or calling `commands/list` activates it.
- Prompt text and code-mode changes go through launch files and apply on the next native turn; they never restart the process. CLI, environment and additional preset plugin changes go through provider transitions. Releasing a session stops its owned native work; unconfirmed work ends with the process, never by restarting a Host other sessions use. A Host loss fails every attached session recoverably without stopping work, since retirement ends the process. The one exception is an unresolved fork (below), which retires the shared process.
- Preserve the saved native store and preset across resume/forks. The two chat preset ids (`claudian-code` is legacy) keep identical content; code mode is a live per-agent presentation, not a preset choice. User plugin rows only extend chat presets after Claudian's own rows and never replace them. Auxiliary tool policy stays fixed for the lifetime of its Agent.
- Native streams have independent ordering and coalescing. Correlate requested turns with the prompt request ID, rebaseline owned jobs at turn completion, and use native child catalog modes. Unknown state remains busy until reconciliation or bounded failure disposal.
- Core output is append-only. Divergent streamed attempts require invalidation and reload guidance; cold hydration must still recover committed messages after failed attempts. Discarding an auxiliary task or side chat releases its claim and never deletes native transcripts.
- Auxiliary tasks and side chats are ephemeral: the bundled plugin decorates native's mounted persistence backend through its public seam (never replaces it) and keeps prefixed roots, token-claimed forks and their children in Host memory, out of the projection cache, of workspace, archive and pin sets, and of native's spill root. The execution session alone decides ephemerality from its lifecycle and the lease's readiness, falling back to native storage when the plugin is not ready; the Host alone mints ephemeral identities, offers fork tokens and runs one fork at a time so no other fork can claim one. Native forks cannot be cancelled: no client deadline ends one, and any fork failure native did not refuse retires an ephemeral-capable process before its token is withdrawn, and a fork outliving the Host watchdog always retires its process. An ephemeral session ends with its process generation: never resume, re-fork, archive or unarchive it. On every supported dsh version change, verify against real dsh that ephemeral roots, side-chat forks and their subagents (including oversized tool output) leave nothing under DSH_HOME or the spill root and stay out of a concurrent dsh web's workspaces; the plugin relies on the seam, `session/event` routing, header lineage, the spill store and the projection-cache and workspace domains.
