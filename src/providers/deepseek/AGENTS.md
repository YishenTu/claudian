# DeepSeek Harness constraints

- Preserve the user's selected native Web or Desktop profile, credentials, model defaults and MCP configuration. Native Desktop-only installations must work with the bundled runtime, without npm dsh, system Node or a Web profile. Desktop's bundled `dsh` command and Windows npm `.cmd`/`.ps1` shims locate installations and are never spawned: run Desktop's executable as Node on its bundled Host CLI, and npm dsh through Node on its package entry. WSL requires Linux Node and the Linux npm dsh package with the user-configured Web profile in that distro; a Windows Desktop install is never a WSL installation or grounds to create a profile. Presets are invocation overlays; do not provision a Claudian profile or reconstruct native configuration. The four bundled plugins stay narrow: compatibility (literal per-session prompt files, live chat code-mode presentation and native auxiliary tool restrictions), lifecycle (exit when Claudian's end of stdin closes) ephemeral (below) and sessions (chat presets only, forwarding Claudian session tools; owns no session state). Harness owns tool execution, permissions and persistence.
- One workspace-owned `DeepSeekHost` runs a single native process for every DeepSeek session and history read. Only it starts, reconnects or stops the process; sessions attach through leases. `DeepSeekRoster` is the only subscriber to process-global streams and routes interactions to the nearest claimed subagent ancestor; forks name their source as native parent but are independent roots. A native session has at most one claimant per Host.
- Session tools use one call route per native Host, with caller identity from `exec.agent.id` resolved through the roster claim. WSL calls use the shared call-mode relay; route credentials enter only the per-call relay environment from the existing private endpoint file, never the Host launch environment (shared shell capture writes exports to a temporary file), generated code or argv. Relay stdin remains open until response or cancellation. Calls use the owning run's policy and cancellation lifetime; ownership is checked against the run captured when the call arrives, denying unbound callers and callers owned by another run. The sessions plugin rereads its private endpoint file on every call, never shadows native `send_message`, and requests no native approval.
- Native exposes no close-session RPC: touched sessions keep their writers, and ephemeral sessions their memory, until the process stops. A second process claiming one gets `session/writer-held`; never remove native locks to make a read or resume succeed. Read cold history through projections and fixed-cut pages, and pre-session skill catalogs through `skills/list`; following a cold child or calling `commands/list` activates it. `session/create` reuses a named session only while it is blank, so a saved session resumes through that activation, never through create; activation runs in the session's recorded directory, so first check its listed `cwd` against the vault.
- Prompt text and code-mode changes go through launch files and apply on the next native turn; they never restart the process. Concurrent sessions on one Host may need different prompts, so prompts are keyed by native session, never by preset: only the session's claimant writes its prompt, and releasing the claim removes it. CLI, environment and additional preset plugin changes go through provider transitions. Releasing a session stops its owned native work; unconfirmed work ends with the process, never by restarting a Host other sessions use. Native's heartbeat drops stalled clients, so the Host alone recovers the transport: it reconnects a live process, again after every drop, within a bounded budget before it counts as a loss, and closes superseded sockets. Host recovery, from a reconnect's reset until its new roster baseline, pauses observer waits and Stop deadlines, and a retired process ends them; other unready states keep their deadlines. Only user intent stops native work: a Stop in progress or closing the conversation. Any other session failure keeps the binding retained, so the work stays visible and a later Stop or close can still end it, until the next send releases it and rebinds. A Host loss fails every attached session recoverably without stopping work, since retirement ends the process. The one exception is an unresolved fork (below), which retires the shared process.
- Preserve the saved native store and preset across resume/forks. Web and Desktop profiles share the store at DSH_HOME; saved profile provenance is not a separate store boundary. Resolve DSH_HOME by native's rule in the child environment (USERPROFILE, not HOME, on Windows) and compare native Windows stores case-insensitively. WSL uses Linux HOME and case-sensitive Linux store paths, scoped to its resolved distro; do not probe Linux homes synchronously from metadata projections. The two chat preset ids (`claudian-code` is legacy) keep identical content; code mode is a live per-agent presentation, not a preset choice. User plugin rows only extend chat presets after Claudian's own rows and never replace them. Auxiliary tool policy stays fixed for the lifetime of its Agent.
- Native streams have independent ordering and coalescing. Correlate requested turns with the prompt request ID, rebaseline owned jobs at turn completion, and use native child catalog modes. Unknown state remains busy until reconciliation or bounded failure disposal.
- Steer only into the claimed, running requested turn: native `mode: 'steer'` starts a new turn when none runs. A steer is accepted when a step boundary claims it, not when native acknowledges it. Native cancel keeps its inbox, so withdraw unclaimed steers before cancelling; only a confirmed removal returns a steer as unsent.
- Core output is append-only. Divergent streamed attempts require invalidation and reload guidance; cold hydration must still recover committed messages after failed attempts. Discarding an auxiliary task or side chat releases its claim and never deletes native transcripts.
- Auxiliary tasks and side chats are ephemeral: the bundled plugin decorates native's mounted persistence backend through its public seam (never replaces it) and keeps prefixed roots, token-claimed forks and their children in Host memory, out of the projection cache, of workspace, archive and pin sets, and of native's spill and attachment stores. Ephemeral image admission, tool images, request variants and upload indexes must leave no native residue; inherited/shared durable images remain native and must never be moved or deleted. The execution session alone decides ephemerality from its lifecycle and the lease's readiness, falling back to native storage when the plugin is not ready; the Host alone mints ephemeral identities, offers fork tokens and runs one fork at a time so no other fork can claim one. Native forks cannot be cancelled: no client deadline ends one, and any fork failure native did not refuse retires an ephemeral-capable process before its token is withdrawn, and a fork outliving the Host watchdog always retires its process. An ephemeral session ends with its process generation: never resume, re-fork, archive or unarchive it. Claudian does not gate the native version; whenever the tested dsh version changes, verify against real dsh that ephemeral roots, side-chat forks and their subagents (including oversized tool output, input/tool images, inherited images and successful Files API uploads) leave nothing under DSH_HOME or the spill root and stay out of a concurrent dsh web's workspaces; the plugin relies on the seam, `session/event` routing, header lineage, the spill and attachment APIs, native Agent initiator context, and the projection-cache and workspace domains.
