# AI Edit Reviews

- `AiEditHighlightController` owns pending review state and validates restored records. `AiEditReviewStorage` owns ordered Vault-local I/O through the core `AiEditReviewPersistence` port. Do not store reviews in provider transcripts or plugin settings.
- Disposal removes editor decorations and timers, never durable pending reviews. Acceptance, reversion, explicit clearing, and file deletion update the saved state; unresolved positions remain retained rather than guessed or silently discarded.
- Overlapping AI edits compose against the first unreviewed original, including partial overlaps and deletion boundaries. Reversion restores that original; acceptance and manual edits establish a new baseline. Returning to the original removes the net-zero review.
- Keep unchanged pending blocks anchored while composing later edits. A whole-document re-diff against every original can pair repeated formulas with another occurrence and move an unrelated review.
- Compare logical LF lines, including disk captures and provider diff lines, without rewriting the note's on-disk line endings. Restored CRLF-contaminated review blocks must be normalized and re-diffed before rendering.
- Obsidian adapter rename rejects existing destinations. Review storage must rotate the previous document to a recoverable backup before promotion and restore it if promotion fails; startup must handle an interruption between renames.
- User-annotated CodeMirror transactions dismiss only intersected review blocks; map surviving anchors through the transaction. External reloads and plugin reversion are not manual input. Never dispatch synchronously from an editor update listener.
- Persist review anchors as paired W3C-style `TextPositionSelector` and `TextQuoteSelector` data. Position offsets are Unicode code points on disk but must be converted to CodeMirror UTF-16 offsets for transaction mapping; resolve the exact position first, then quote plus prefix/suffix and position proximity, and leave an exact tie unresolved.
- The feature is experimental and defaults off. Its enablement switch stops active captures and removes editor decorations without deleting durable pending reviews. Re-enabling restores resolvable reviews; path rename/delete maintenance remains active while display and capture are disabled.
- `VaultEditCapture` holds one compressed Markdown baseline per path shared by active turns, reads sequentially, and releases it when idle. Await initial capture before provider handoff and reconcile on every settlement, including errors/cancellation. Never evict an active baseline merely to meet a memory quota: arbitrary shell writes require the original. Persist review blocks, not whole-Vault snapshots.
- Request-level captures are fallbacks for operations without early structured tool notifications. Advance their baseline when a tool edit is already recorded or reverted so completion cannot recreate an approved review.
- Verify restoration and approval through the controller with real CodeMirror state and the application storage implementation, mocking only the filesystem/Obsidian boundaries.
