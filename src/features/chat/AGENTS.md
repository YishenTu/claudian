# Chat constraints

- Conversation, persisted tab identity, runtime tab, hydration, and provider execution have independent lifetimes. Layout/selection/hydration cannot create provider execution, rewrite durable identity, or cancel another tab's turn.
- The main-owned session pool owns execution across tab rebind and view close. A detached draft has no conversation to be found by: it is disposed when idle unless a presentation holds it (`holdDraft`) to reattach by its session key. Attachment is exclusive and reserved before awaiting hydration; detach uses the exact issued handle. Only Stop or plugin shutdown cancels admitted session work.
- Provider resources release after 30 idle minutes independently of attachment. Detached main models release only after queued input, recovery, interactions, saves and auxiliary work settle; release repository history through its guarded cache API too. Compact selections and review attention survive model release.
- Tabs are a compact-layout concept. Entering wide unloads every tab to its identity (an unloaded blank tab holds its draft session in the pool and reattaches it by key); the viewer slot's single provisional preview is the only presentation, wide actions (input, pin, fork) never retain it, and wide navigation never assembles a narrow tab. Unsent text no presentation shows is held per session in `ParkedDrafts`. Leaving wide hands the shown session back to its narrow tab (or turns the preview into one) and must finish closing other previews before exposing controls that could target closing tabs.
- Persist view-scoped tab identities only, never composer drafts, hydrated messages, DOM, turns, or lifecycle values. Exception: an active preview persists with a `preview` marker so the wide selection survives reload; it restores provisional only in the wide layout. Restore inactive tab identities before one final activation. Provider command discovery runs only on demand for the active tab (live session snapshot first, then an isolated metadata probe); it never runs eagerly and cannot create chat sessions.
- Restore follows Obsidian's delivered state, not early onOpen synthesis, and starts after layout ready. Same-instance reopen uses the finalized shutdown snapshot. Versioned snapshots reject malformed/duplicate identities as a whole. Adopt metadata for all tab identities selected by the restore policy before restoring them; deferred history scanning owns other sessions.
- View shutdown joins navigation and in-progress conversation creation before sealing its tab identity snapshot; it never drains running responses. Plugin shutdown fences the pool synchronously and drains detached sessions before provider teardown. While restoration is pending, its full plan remains the persistence authority, not partially assembled membership.
- First canonical input freezes Linked content for both creation and provider context. Create failure restores the draft; post-create failure leaves a locked conversation whose retry is still the first turn. Later/steered/compact turns must not resend it through a mutable sent flag.
- Blank-tab provider transitions serialize and roll back to the last stable draft. Model-picker intents affect only the selected tab/conversation and the future-tab seed; existing tabs must not subscribe to that seed.
- A provider-reported missing session can delete its record from inside its own turn. Retire that session only after the turn settles, so queued and unsent input reaches the attached composer before the tab resets. The pool disposes a deleted conversation's session once it is detached and idle; unreachable detached recovery is discarded with it.
- A steer or async answer returns to the composer or queue only when definitely unsent; accepted or uncertain delivery is reconciled from provider echo/history and never resent.
- Open response blocks, tool/subagent records, and pending interaction answers must survive absent presentation. Detach cancels view jobs and releases DOM; it does not finalize blocks or settle requests.
- Deferred presentation work (indicators, prompt resumes, scheduled renders) is fenced by the stream generation that scheduled it; never apply it to whichever turn is current.
- Conversation authority is revalidated after session preparation immediately before provider handoff. Superseded preparation cannot install or publish resources.

## Surface and input behavior

- Model selection alone must not change displayed context usage. Retain the previous complete report until the new model reports a usable window; never combine one model’s token count with another model’s window.
- Render and submit model/reasoning from the same destination-owned settings. Submission cannot rederive them from provider-wide defaults.
- One composer serves every destination, and its target is derived from presentation state rather than a separately mutable selection. User-originated sends and cancels resolve the target when they run; internally queued main work keeps the owner it was admitted with and must never read the current target at dispatch.
