# Test constraints

- Use package test commands: `npm run test:unit -- --runTestsByPath <path>` runs either a unit or integration Jest file with the required Node local-storage option. `npm run test` also runs script/architecture/config checks; targeted Jest does not.
- Before adding a test, identify the observable contract, a plausible regression it would catch, and why existing coverage would miss it. Extend an existing case or table when it already owns that contract; additional test layers need a distinct failure mode.
- Maintain affected tests alongside implementation changes. Revisit coverage when branches, callers, ownership, or dependencies change. Consolidate redundant cases and remove obsolete fixtures, mocks, and test-only production code in the same change.
- Tests must exercise the behavior they claim; mocks must not supply the transformation, persistence, admission, or ordering being asserted. Integration tests keep interacting owned modules real; use narrow public ports only for environment, Obsidian, provider, or other dependencies outside the behavior under test.
- Assertions must distinguish correct behavior from the relevant fault, with independently grounded expected results. Negative fixtures must reach the intended guard; asynchronous assertions must observe the lifecycle point where the failure could become visible.
- Before removing or consolidating coverage, identify retained proof for each meaningful assertion or establish that the behavior is retired. Carry missing assertions into the keeper first. Passing tests alone do not establish equivalent coverage; use a targeted fault check when equivalence is uncertain. Absence of repository-local callers is insufficient to retire an externally reachable plugin or compatibility contract.
- Preserve separate cases for distinct protocol, platform, security, lifecycle, persistence, and compatibility failures. Small tests, static checks, and implementation-shaped assertions may protect independent contracts; judge their evidence, not their appearance.
- Do not add production facades solely for testing, or APIs or state solely to expose implementation details to tests.
- Express fixture timestamps with `@test/helpers/testClock`, which captures a current-time baseline for each test module environment. Derive related creation, expiry, and assertion dates from that timeline; share one injected clock across interacting services and advance it explicitly for expiry tests. Do not add fixed calendar anchors. CI also runs selected Jest tests about three years ahead under libfaketime.
- Shared provider changes need neutral-contract coverage and distinct native adapter cases.
- DOM interaction and accessibility regressions need real-DOM tests with Testing Library role/name queries and targeted `jest-axe` checks. Isolated controller logic may use unit tests without a DOM; `MockElement` class/tag assertions do not establish accessibility or keyboard behavior.
